# スキルマーケット：権限・安全性・最終検証報告

## 実装概要

- 未ログイン時、出品作成・編集、予約、注文、取引詳細へのアクセスをログイン画面にリダイレクトし、ログイン後の戻り先を指定。
- 提供者プロフィールがない場合の登録案内、取引当事者・管理者のアクセス制御、資格確認済み表示の承認条件を確認。
- 固定・時間単価の金額必須と正値、予約日時の前後関係、公開カテゴリ・取引方式・資格確認の検証を強化。プロキシ経由の画像URLも検証できるよう修正。
- 資格確認が必要なカテゴリの案内、送信中表示、二重送信の防止、見積フォームのモバイル幅表示を改善。既存の空状態表示と決済「準備中」表示を確認。

## 検証結果

- `npm run typecheck`、変更ファイル対象の ESLint、`npm run build`：成功。ビルドは Supabase の公開URL・公開キーを設定した状態でも成功。
- 開発DBのカテゴリ：全10件、公開7件。トップページに公開カテゴリと出品の空状態が表示されることをHTTPで確認。
- 未ログイン時：出品作成・編集、予約、相談、注文、予約・注文詳細、管理画面はログイン画面へHTTP 307でリダイレクト。
- 開発DB上で、トランザクション内に一時ユーザーを作成し、`authenticated` / `anon` ロールとJWTのユーザーIDを切り替えてRLS・RPCを検証。出品の作成→公開→匿名からの参照、第三者による取引参照・予約承認の拒否、未来の予約を完了できないこと、未承認の資格バッジと資格要件付き出品の拒否、承認済み資格の参照と出品、注文の相談→見積→注文→作業中→納品→完了、予約・注文のレビュー投稿を確認。
- 予約の完了は、トランザクション内で用意した過去日時の予約を使い、requested→accepted→completed→reviewedを確認。未来日時で通常作成した予約はrequested→acceptedと、終了前の完了拒否を確認。PostgreSQLのトランザクション内では現在時刻が固定されるため、同一の未来予約を時間経過後に完了する実時間試験は未実施。
- 試験データはロールバックし、ユーザー、検証用カテゴリ・出品・レビューが残っていないことを確認。架空の実績や口コミを公開データとして作成していません。

## 環境・DB・外部サービス

- 必須：`NEXT_PUBLIC_SUPABASE_URL`、`NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`（既存の代替名 `NEXT_PUBLIC_SUPABASE_ANON_KEY` も利用可能）。ブラウザ用の公開値はビルド時にも必要です。サービスロールキーをクライアントに設定しないでください。
- 開発DBには既存の `initial_schema`、`commercial_security`、`marketplace_legacy`、`platform_pivot`、`public_marketplace_access` の5マイグレーションが適用済み。今回の追加DB変更はありません。別環境には既存マイグレーション、RLS・RPCおよび画像ストレージ設定が必要です。
- メール認証・Googleログインを利用する環境では、Supabase Auth のプロバイダー設定と、利用するサイトURL・認証コールバックURLの許可が必要です。AI相談は `OPENAI_API_KEY` 未設定時、実際のAI生成ではなく入力内容を使うフォールバックです。
